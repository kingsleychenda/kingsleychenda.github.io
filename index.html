🔍 What Gets Checked

Each address listed in your sitemap is visited and inspected. You do not need to configure anything to get these checks — they run automatically.

Sitemap structure and protocol

The sitemap file itself is validated against the sitemap protocol: the format, the required elements, date formats, address encoding, and whether the sitemap is reachable and readable at all. Problems here often explain why a search engine ignores a sitemap entirely.

Status codes and redirects

Every URL is requested so the tool can see what the server actually returns. Pages that are gone, pages that were moved, and pages that bounce through several redirects before arriving somewhere are all flagged. Redirect chains in particular waste time for both visitors and search engines.

Soft 404 pages

Some servers return a normal "success" response while the page itself says the content no longer exists. These are called soft 404s, and they are easy to miss without a crawler looking for them.

Noindex warnings

If a page is listed in your sitemap but also tells search engines not to index it, that is a contradiction. The tool points out every conflict so you can decide which one to change.

Canonical mismatches

The canonical tag tells search engines which version of a page is the main one. When the canonical points somewhere unexpected compared to what the sitemap lists, the tool records it so you can review the page.

Hreflang problems

Websites with more than one language use hreflang tags to connect translations. Missing, mistyped, or one-directional hreflang entries are collected so you can correct the language setup.

Robots.txt awareness

The tool respects and reports on robots.txt rules, so blocked pages show up as blocked rather than as mysterious failures.
